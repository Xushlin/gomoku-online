## MODIFIED Requirements

### Requirement: 对比度按渐变的每一档量,而方向取决于文字的明暗

主题的对比度校验 SHALL 对**每一个渐变色标**取值,而 MUST NOT 只对平色回退值取值 —— 一个按回退值合格的按钮,可能在它自己渐变的某一档上不合格(量到过 4.85 对 3.21)。

**最差的那一档取哪一头,取决于文字是深还是浅:** 深色文字落在浅色渐变上,最差是**最暗**那一档;浅色文字落在深色渐变上,最差是**最亮**那一档。取反会得到一个偏乐观约 1.3 倍的数字,而那个数字看起来完全正常。

**全部**主题的明暗两套 × 全部前景色 MUST ≥ 4.5:1 —— 不只是 `qq-game`。

**而「全部前景色」SHALL 按组件实际写出来的配对取值,不是按 token 的名字。** 校验 SHALL
走查模板里每一个角色 utility 的出现处、取与它**同现**的前景 utility,以那个配对为判据;
MUST NOT 手写一份「主题 → 前景 token」对照表 —— 那是本仓库判过六次的那个形状。

**这一条是量出来的,而它修的是一条已经绿着的检查。** 上一版校验取的是前景 token 各自落在
**它自己的**面上,而 31 个 `control-primary` 按钮里有 25 个把 `--color-bg`(一个**背景**
token)当字色用:qq-game 浅色 3.57:1,暗色 **1.58:1**(近黑的青落在深红上)。那个配对
**从来不在校验的定义域里**,所以校验一直是绿的。**检查量的是对的东西,应用做的是另一件事;
两边都没有错在自己那一侧。**

同一条缝的另一头:`--color-on-primary` 在三套主题的暗色里是字面量 `#ffffff`,而它们暗色的
强调色是**浅**色 —— 白字落上去 1.75 / 2.62 / 2.94。**两种写法各在不同的主题里读不出来**,
所以判据不能是「选哪一个 token」,只能是「量组件写出来的那一对」。

#### Scenario: 按最差档判定
- **WHEN** 一个前景色落在一个多档渐变上
- **THEN** 判据是它与全部色标之间的**最小**对比度

#### Scenario: 探针自己可以变红
- **WHEN** 把前景色设成与背景同色
- **THEN** 测得的比值 < 4.5 —— 一条测不出错的对比度检查证明不了合格

**而在量那一对之前,先要保证「那一对」是确定的:一个状态里 MUST NOT 出现两个不同的
前景色 utility。** 它们同特异性,谁画取决于样式表顺序 —— 量到过 `text-text` 赢掉同一个
元素上的 `text-bg`,于是那个 `[class.text-bg]` 一次都没生效,而模板上它看起来是对的。
**一个被静默覆盖的 class 和一个生效的 class 输出完全相同。**

#### Scenario: 配对不是手写的
- **WHEN** 一个模板把某个前景 utility 写在 `control-primary` 上,而**不**改 `check-styles.mjs`
- **THEN** 那个配对自动进入校验范围;它在任何主题 × 明暗下 < 4.5 即失败,并点名主题与配对

#### Scenario: 背景 token 当前景用会被拦住
- **WHEN** 某个按钮写成 `control-primary text-bg`
- **THEN** 校验按「`--color-bg` 落在 `--color-primary` / `--control-image` 上」取值 —— qq-game
  暗色下量到 1.58,失败。**不需要另写一条「不许用 `text-bg`」的禁令**

#### Scenario: 探针对新配对也能变红
- **WHEN** 把某套主题的 `--color-on-primary` 设成它自己的填充色
- **THEN** `npm run lint` 失败并点名该主题 —— 一条量不出错的检查证明不了合格
#### Scenario: 一个状态里两个前景色
- **WHEN** 一个元素静态带 `text-text`,并在某个条件下再加一个 `text-on-primary`
- **THEN** 校验失败并点名这两个 class —— 判据是**可能同时在元素上**,而不是谁赢
