# 手机端的声音

## 为什么

真机反馈的四条里,这是唯一还没动的一条:「设置主题,棋盘颜色,声音的都没有」。前三条 `add-mobile-settings` 已经答了(而棋盘颜色不是独立轴,是主题的一部分)。声音是真的**一点都没有** —— 这个客户端连音频层都不存在。

## 这一笔和前面每一笔都不一样:**它拉不动 web 的东西**

i18n 和主题 token 都是从 `frontend-web` 同步过来的,`shared_sync_test` 盯着不许漂。声音**没有可同步的东西**:web 的三个音效包是用 **WebAudio 现场合成**的(`play(event, ctx: AudioContext, masterGain: GainNode)`),仓库里**一个音频文件都没有**。

所以这里要移植的不是素材,是**设计**:哪个事件用什么频率、多长、多大声 —— 那些数字明明白白写在 web 那三个包的源码和文档注释里。

## 而这带来一个别处没有的判据

**合成出来的音频就是一串数字,所以它是可断言的。** 我听不见声音,但可以量:

- `move-place` 生成的样本数对应 ~80 ms;
- 峰值幅度落在预期区间(不削顶、也不是全零);
- **主频接近 660 Hz** —— 用过零率或 Goertzel 直接从样本上算。

一个「播放音效」的功能通常只能靠人耳验收。这一笔不是。**而这正是选「合成」而不是「打包音频文件」的主要理由之一** —— 文件是二进制,只能断言它存在。

## 做什么

- `SoundEventName` —— 事件集**从 web 的 `SOUND_EVENTS` 派生**(源码走查,和 `hub_contract_test` 从服务端源码派生 hub 方法名同一招),不手写清单。
- 一个纯 Dart 的合成器:正弦/方波 + 指数衰减包络 → 16-bit PCM → 内存里的 WAV 字节。**没有资产文件。**
- 一个音效包(移植 web 的 `minimal`),**没有包注册表**:一个只有一条分支的开关还是开关。触发条件写下来。
- 设置页一个开关(`header.sound.label` / `on` / `off`),持久化到已有的 `PreferencesStore`。
- 在已经存在的事件点上播:落子、吃子、被催、赢/输/和。

## 明确不做

- **音量滑块。** 文案(`header.sound.volume`)在,但音量要多一个持久化值、一个控件、和一套「静音与音量为 0 有什么区别」的判断。**触发条件:有人说吵。**
- **音效包选择。** 文案有三个包名,而这里只有一个包 —— 一个只有一项的单选组不是选择。**触发条件:第二个包落地。**
- **iOS 验证。** 手上只有一台安卓机。
- **让声音「好听」。** 移植 web 的设计参数,不重新调音。

## 已知的风险,写在前面

**加插件在这个仓刚出过事**:`shared_preferences` 落地之后 Android 构建直接过不去(#192)。所以插件的选择标准里包含「最主流、最少原生代码」,并且**这一笔必须以一次真机安装收尾**,不能只跑测试就算完。
