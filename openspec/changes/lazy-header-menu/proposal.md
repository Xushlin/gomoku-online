# lazy-header-menu

把 `@angular/cdk` 从首屏挪出去 —— 它的**唯一** eager 导入者是 header 那一组下拉菜单。

## Why

**量出来的,而且是重新量的**(那条延期项写下的数字是几个变更以前的):

| 首屏归因 | |
| --- | --- |
| `@angular/core` | 126.69 kB |
| `@angular/router` | 71.91 kB |
| **`@angular/cdk`** | **77.13 kB** |
| **我们自己全部的代码** | **52.12 kB** |
| `@angular/common` | 35.32 kB |

**一组下拉菜单比我们整个应用的代码还大 1.5 倍。** 拆开看:overlay 34.17、menu 18.69、focus-monitor 6.07、portal 5.02、list-key-manager 4.27、scrolling 3.03,余下十来个小块。

**打桩量过上限:** 把 `header.html` 里所有 `cdkMenu*` 绑定与 `header.ts` 的 import 拿掉,初始包 **477.83 → 396.42 kB(−81.41)**。比 cdk 的 77.13 还多 4 kB —— 连带掉的是模板里那部分编译产物。

**而「唯一的 eager 导入者」这句话是查过的,不是抄延期项的。** 全仓 13 处 `@angular/cdk` import:
- `header.ts` → `@angular/cdk/menu`,**shell 的一部分,所以 eager**;
- 其余 12 处全是 `@angular/cdk/dialog`,而它们**都在懒加载路径上** —— 包括 `active-rooms.ts` 与 `lobby/cards/ai-game.ts` 这两张卡片:它们看起来在「大厅」里,而 eager 的 `Lobby` 组件 `imports` 里**没有它们**(那两张属于 `g/:gameKey/lobby`,懒加载)。上面那次打桩把 overlay 一起量掉了,反过来证明了这件事:如果 Dialog 是 eager 的,overlay 会留下,省的就只有 ~24 kB。

预算余量现在是 **2.2 kB**。这一条不做,下一个稍有体积的前端改动就会超。

## 硬约束

- **手搓下拉是明令禁止的**(焦点陷阱 / ESC / backdrop / ARIA)。所以「拿掉 CDK 自己写一个」不在选项里。
- 那条延期项自己写着可接受的代价:**「懒加载菜单要让首次点击等一个 chunk」** —— 是等,不是丢掉一次点击。

## What Changes(方案 A,推荐)

把 header 那六个外观控件连同它们的菜单搬进一个 **`@defer`** 块:

```
@defer (when menuRequested()) {  <app-appearance-menus … />  }
@placeholder { …六个按钮,视觉一致,但不带任何 cdk 指令… }
@prefetch (on idle)
```

- 占位里的按钮**只做一件事**:把 `menuRequested` 置真。
- 加载完成后 `AppearanceMenus` 渲染真正带 `cdkMenuTriggerFor` 的同一组按钮,并对**刚才点的那一个**调 `CdkMenuTrigger.open()` —— 于是那一次点击最终会把菜单打开,而不是被吃掉。
- `@prefetch (on idle)` 让 chunk 在空闲时就下来,所以「等」在正常网络下是 0。

**它保留今天的交互与断点行为**(`lg` 以上六个控件在行内、以下折叠进 Settings),所以那条既有要求只需要补一句「菜单是懒加载的」。

### 这个方案要付的代价,写在明处

占位与真身**是两份按钮标记**。本仓库对「一份副本看起来是对的」有过教训,所以配一条测试:**渲染占位与加载后的两种状态,断言按钮的可见文案与 `aria-label` 逐一相等** —— 判据从 `pickers` / `toggles` 两个生产数组推导,不手写清单。

## 考虑过但没选的(B):把下拉换成一个 CDK Dialog

一个「外观」对话框,列六个控件,所有宽度下都由 Settings 按钮打开。**零重复**,而且直接复用本仓库已经有的懒加载弹框套路(`openLeaveConfirm` 那个 —— 守卫连 `Dialog` 一起动态 import,已经证明 cdk 可以完全不进首屏)。

代价是**桌面端可见的变化**:`lg` 以上那一排「主题:游戏厅 / 棋盘:木纹 / …」当前值不再常驻,要点开才看得到。**没选它的理由就是这个** —— 这次要的是那 77 kB,不是一次重新设计;A 的代价(两份按钮标记)是可以用一条推导出来的测试钉住的,而 B 的代价是用户看得见的。如果 A 的重复日后真的开始漂,B 仍然在这里。

## 判它成不成

- **判据是构建产物的归因,不是「它是懒加载的」这一推理** —— 既有那条要求自己写着这句话。所以第一步就是把 `@defer` 搭起来、构建、跑归因脚本,确认 `@angular/cdk` **不在**从 `index.html` 那个脚本静态可达的输出集合里;**在写任何界面细节之前**。
- 初始包目标:**< 400 kB**(上限量到是 396.42)。低于预算 480 的余量从 2.2 kB 变成 80+ kB。
- 菜单仍然能用:一次点击之后菜单打开(不是两次);ESC 关得掉;键盘上下键能走 —— 这三件是 CDK 给的,而测试要证明我们没有把它们弄丢。
- **而「测试绿」不等于「浏览器里能用」**:第一版同步调 `open()` 在 jsdom 里全绿,在浏览器里菜单**开了又立刻被关掉**(发起的那次点击还在冒泡,CDK 的「点到外面就关」接住了它的尾巴)。所以浏览器里点那一下是**必须**的一步,不是锦上添花 —— 详见 tasks §7。
- 375 px 下 header 仍然不换行、不横向溢出(既有那条要求钉着)。
