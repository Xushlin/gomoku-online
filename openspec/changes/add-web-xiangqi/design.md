# 设计决策

## D1 —— 初始摆子放在哪一边

**问题.** 要画出象棋盘，必须知道初始摆子；着法历史里只有 `from → to`，推不出「第 0 步之前谁在哪」。五子棋没有这个问题，所以既有的前端从来不需要回答它。

**三个选项.**

| | 做法 | 代价 |
| --- | --- | --- |
| a | 前端持有一份初始布局，重放着法推导盘面 | 一份复制 |
| b | 服务端在 DTO 里下发盘面投影 | `IGameRules` 增加一个只有象棋需要的成员，`RoomStateDto` 增加一个字段 |
| c | 把象棋规则移植成 TypeScript（顺带能高亮合法着法） | 第二份真源 |

**选 a.**

(c) 立刻出局。这个仓库对第二份真源的表现已经有过一句总结：不一致的表现是「客户端说能走、服务端说不能」，玩家会当成 bug，而**我们没有任何机制会发现它**。

(b) 看起来最「正确」，但它要往刚刚清空的地方重新塞东西。`generalize-match-domain` 的全部成果就是把盘面语义从 `Room` / `Game` / `Move` 里拿掉，`add-xiangqi` 的验收条件是那三个文件一行没改。为了画一块盘，把「盘面投影」加回聚合根的对外契约，是把那笔账倒着还回去。而且它对五子棋是纯负担 —— 五子棋的盘面本来就能从历史平凡地推出。

(a) 是一份复制，按本仓库已经写下的判据衡量它：

> 一份复制是否可接受，取决于它错了会不会被发现，而不是它有多小。

这一份错了会怎样：**第零步就画错整块盘**。这是所有失效形态里最容易被发现的一种 —— 不需要打完一局，不需要特定路径，打开页面就看得见。第二张网：服务端会拒绝任何在错盘面上「看起来合法」的着法，玩家立刻收到一个错误提示。这两张网与 `GameManifest.board` 当初被接受时是同一对（画错格数 + 服务端越界拒绝）。

还有一个更强的理由：**初始摆子不是服务端状态，它是这个游戏的规则。** 和「棋盘是 10×9」一样公开、一样固定，和「谁走到了哪一格」不是一类东西。象棋的开局摆法一千年没变过，它不会因为服务端改了什么而漂移。

**守护它的测试**：不是「和后端比对」（前端测试到不了后端），而是对这份布局本身的**普查断言** —— 32 枚子、每方 1 帥 2 仕 2 相 2 傌 2 俥 2 炮 5 兵、左右镜像对称、红方全在第 5–9 行。真实的失效模式是打错一个坐标或漏一枚子，普查全都抓得到。

## D2 —— 不做客户端合法着法判定

客户端只做两件**不需要规则**的事：

1. 只能拿起自己的子（看的是子的归属）。
2. 不是自己回合时整块盘只读（看的是 `currentTurn`）。

其余一律交给服务端：点了非法落点 → `MovePiece` 抛 `HubException` → 弹一个可翻译的提示。

代价说清楚：玩家会试出非法着法然后看到一个 toast。象棋的走法比五子棋复杂，这个代价是真实的。但替代方案是 D1 里已经否掉的 (c)，而**一个偶尔多点一次的玩家，好过一套会和服务端悄悄分叉的规则**。

合法着法高亮不是永远不做，而是要等到有一个**单一来源**能供给它 —— 例如服务端在 `RoomState` 里下发当前方的合法着法集合。那时高亮和判定用的是同一份数据，不可能分叉。那是另一个变更，且它有独立的理由（人人对战上线后，高亮对新手的价值大得多）。

## D3 —— 红黑的显示：`Stone.Black` 画成红子

`add-xiangqi` 押的注在这里兑现。`Game` 从 `Stone.Black` 开局，象棋红先，所以本棋种里 `Stone.Black` **就是红方** —— Domain 因此一行都不用改。

代价全部落在这一层，而且就该落在这一层：前端把 `Black` 画成红字、`White` 画成黑字。这是整个变更里唯一一处「棋种特定的语义映射」，它是**显示层的读法**，正是当初那句注释所说的位置。

它需要一条测试盯着，因为读起来太反直觉，很容易被后来的人「修正」回去。

## D4 —— 两块棋盘，一个容器里的 `@if`，不是注册表

`RoomPage` 与 `ReplayPage` 用 `@if (isXiangqi())` 在 `<app-board>` 和 `<app-xiangqi-board>` 之间选。

为什么不做「棋盘组件注册表」（像主题、语言、音效包那样）：那三者的注册表存在，是因为**新增一项是可预期的常规操作**（加一门语言、加一套皮肤）。棋盘不是 —— 对战族只剩 成语接龙，而它根本没有网格盘面；华容道和俄罗斯方块不走房间这条路。也就是说这个 `@if` 已知只有两个分支，且**没有第三个在路上**。

为两个分支建注册表，会用动态组件换掉类型安全的 `[input]` / `(output)` 绑定 —— 拿一个真实的保障去换一个不会发生的扩展。

如果哪天真的出现第三块盘面，那时再抽注册表，代价和现在一样。这一条写进规范，是为了让「为什么不是注册表」有个能查的答案，而不是让后来的人重新推一遍。

## D5 —— 交互是两步，而且第一步可以反悔

点自己的子 → 该子高亮 → 点落点 → 发 `movePiece`。

- 再点同一枚子 = 取消选择。
- 点另一枚自己的子 = 改选它（不是「吃自己」，也不是发一个必然失败的请求）。
- `Escape` 取消选择。
- 请求在飞时整块盘 `disabled`，与 `Board` 的 `submitting` 同一处理。

被拒绝后**保持选中**：玩家多半想换个落点，而不是重新找那枚子。

## D6 —— 只做人机

`SupportsHumanVsHuman === false`，与一字棋同样的收口，理由也同样写在页面上（这局不计分）。区别在于**不能照抄一字棋那句「Hard 档打不赢」** —— 象棋不可能穷举，`add-xiangqi-ai` 明确拒绝了任何「不可战胜」的断言，页面上也不许出现。页面该说的是它实际是什么：限深搜索，深一档看得远一档。

## D7 —— 回放页

`web-replay` 有一条「不引入第二个棋盘渲染层」。它写于只有一种盘面形状的时候，现在需要改。

改的是**约束的表述**而不是它的意图：意图是「不要复制粘贴一份 board 实现到 `pages/replay/` 底下」，这条继续成立 —— 回放页仍然一行渲染代码都不自己写，只是它现在从两个共享组件里选一个。
