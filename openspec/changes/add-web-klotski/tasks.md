**跟着提示通关**：连点 16 次「提示」→ 16 步 → 曹操落到 `grid-area: 4 / 2 / 6 / 4`（即出口）→「曹操出来了！」→ **1 星**（16 次提示）→「新纪录」。第 0 关的 `minMoves` 正是 16，所以每一次提示都真的落在最短路径上 —— 与后端冒烟同一条判据，这次是经过真的 UI。

## 6. 归档前必答

- [x] **6.1 「客户端自己判滑动」与象棋「客户端不判合法性」是相反的选择 —— 它们矛盾吗？**

  不矛盾，而且理由是同一条：**不要制造第二份真源。**

  象棋的走法规则只存在于服务端。把它移植成 TypeScript 就是**新造**一份真源，两份会悄悄分叉，而分叉的表现（客户端说能走、服务端说不能）在玩家看来是 bug，在我们这边没有任何机制会发现。所以那块棋盘什么都不判。

  华容道的规则**本来就必须在客户端**——「滑块移进相邻空格」是画出一次拖拽所必需的知识，不写它连动画都做不出来。这里没有第二份真源可造：那一条规则在两边是同一条，而且服务端最后仍然会把整条路径重放一遍。所以那块盘该判，而且该把合法落点标出来。

  一句话：**判据不是「客户端该不该懂规则」，是「懂了会不会多出一份能分叉的真相」。**

- [x] **6.2 后端零改动。** `git diff --name-only` 里没有 `backend/` 下的任何文件。
