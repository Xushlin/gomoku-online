# fix-three-seat-resign

三人局里不再给一个点了必定失败的「认输」,而那个失败也不再是 500。顺带修掉斗地主叫分那一排的原始键。

## Why

**两件缺陷都是「在浏览器里点一次」找到的,而它们躺在那里很久了。**

### 一、认输在三人局里必定失败,而失败是 500

一局真的三人斗地主,点操作条上的「认输」→ 确认框正常 → 确认 → `POST /resign` 回 **500**。服务端日志:

```
SeatCountNotSupportedException: Resigning needs exactly two seats
to name a single winner; this room has 3.
```

领域层是**故意**拒绝的(`Room.Resign` 要指出唯一的赢家),而两头都错了:

- **前端**在三座位房间照样把按钮画出来 —— 一个点了必定失败的入口。
- **后端**没把这个异常放进映射表(中间件映了七类,不含它),所以它是**未处理异常 → 500**。玩家看到一条通用错误,而服务端其实清楚地知道原因。

**而 `room-and-gameplay` 那条要求早就写下了拆除条件:** 「第一个 `SeatCount != 2` 的棋种落地,届时"认输"对它意味着什么是那个棋种要回答的问题」。斗地主与挖坑都落地了 —— **条件响了,没人接**。这次不假装答出了那个问题,只把中间态止血,并把真正的拆除条件换成一个会响的:**点数阶梯落地那天**(而 `DoudizhuScoring.Settle` 至今没有生产调用者,是同一件事的另一头)。

### 二、斗地主叫分那一排显示原始键

`DOUDIZHU_TABLE.i18nPrefix` 写的是 `game.doudizhu`,而键在 **`cards.doudizhu.*`**(挖坑那份写的是 `cards.wakeng`,是对的)。错一个词,于是牌桌上凡是用前缀拼出来的标签**全都显示原始键**:

- 叫分那一排:`game.doudizhu.no-bid` + `game.doudizhu.bid` × 3 —— **三个叫分按钮长得一模一样,分不出哪个是叫几分。**
- 地主徽标:`game.doudizhu.role-seat`。

**为什么两层测试都没红:**

- `card-table.spec.ts` 挂的是**空翻译树**(`langs: { en: {} }`),所以在那里「显示原始键」是常态,任何断言都不会因此变红。
- 双语对齐那条只比 en / zh 的**键集合是否相等** —— 两边同样都没有 `game.doudizhu.*`,所以它是绿的。

顺带删掉 `roleLabelKey`:**一个读者都没有**(grep 只有接口声明与两份配置),而斗地主那份指的 `…landlord` 在任何前缀下都不存在。一个没人读、值又是错的字段比没有这个字段更糟 —— 它看起来是那个标签的来源,其实模板用的是 `i18nPrefix + '.role'`。

## What Changes

- 操作条:**认输只在 `seatCount === 2` 时渲染**。判据是 `=== 2` 而不是「不大于 2」——后者在描述符还没到达时会说「可以认输」。
- 中间件:`SeatCountNotSupportedException` → **409**,与「房间满了」「不是你的回合」同一组。
- `DOUDIZHU_TABLE.i18nPrefix` → `cards.doudizhu`;两份配置与接口里的 `roleLabelKey` 一起删掉。
- 新增一条**用真 `en.json` / `zh-CN.json` 挂牌桌**的测试:按配置的前缀从语言文件里取出译文,断言它真的画在屏幕上。

## 判它成不成

- 三座位没有认输、两座位有 —— **两头都在同一条测试里**;再加一条「描述符还没到达时也不给」,因为那正是 `=== 2` 与「不大于 2」唯一分得出来的地方(变异证明:少了它,两种写法等价)。
- 把前缀改回 `game.doudizhu` MUST 让新测试变红,并**点名缺的是哪个键、哪个语言文件**。
- 409 那条没有测试可挂 —— **仓库里没有 `Gewu.Api.Tests`**。所以判据是**在浏览器 / curl 里真的打一次那个端点**,把状态码写下来。
