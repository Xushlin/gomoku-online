## Why

斗地主规则草案已审定(2026-08-18,家规八条逐条落定)。这个变更落地其中**纯函数的那一半**:牌、牌型识别、压牌、发牌、计分。

**不接内核** —— 没有 `IGameRules` 实现、没有注册、没有迁移。理由是这一半可以完全独立地被证明,而接内核那一半要动 `Game`(发牌需要一份服务端侧的对局设置),那是另一个决定,不该和"四带二算不算炸弹"挤在同一个 PR 里。

## 一个发现:出牌**不需要**第四种载荷

`Move.Text` 的上限是 64 字符,而一手牌最多 20 张(地主的全部手牌)。给每张牌一个字符的编码之后,一手牌是 ≤20 字符 —— **现有的文本载荷就装得下。**

所以 `generalize-match-payload` 当年留的触发条件「真出现不规则走子时再加列」**不成立**:一手牌是常规的文本内容,与成语接龙的一个成语同类,不是新的维度。省掉一整个使能变更。

编码是持久化格式,所以它被钉到了字节:`3♣ = 'A'`、`2♠ = 'z'`、小王 `'@'`、大王 `'#'`。刻意避开引号、逗号、反斜杠 —— 一个持久化格式不该需要读它的人先想清楚转义了几层。

## What Changes

- `Card` / `CardRank` / `CardSuit` —— **点数的数值就是大小顺序**,所以比大小是整数比较。3 < … < A < 2 < 小王 < 大王(斗地主序,不是扑克序)。花色不参与任何比较。
- `CardCombo.Recognise` —— 14 种牌型;认不出来返回 `null`。
- `CardCombo.Beats` —— 同牌型、同长度、依据更大;炸弹与王炸是两条例外。
- `DoudizhuDeal.FromSeed` —— 17/17/17 + 3,可复盘。
- `DoudizhuScoring.Settle` —— 底分 × 倍数,三人得分之和恒为 0。

### 洗牌不用 `System.Random`

与俄罗斯方块同一条理由,而且更硬:`System.Random` 的算法在 .NET 版本之间变过,而一副牌必须在任何运行时上都发得一模一样 —— 否则升级一次运行时,所有历史对局的重放都会读出别的牌。用写死的 xorshift32,与 `TetrisPieceSequence` 同一个实现。

### 发牌结果 MUST NOT 发给客户端

`DoudizhuDeal.Encode()` 的输出就是三家的底牌。它是**服务端侧的对局设置**,与成语纵横「答案不出服务端」同一条:*客户端算不出来的东西,客户端就骗不了*。

这也是为什么它 MUST NOT 从对局 id 之类的公开值派生 —— 那等于把所有人的手牌印在客户端能读到的地方。

## 变异测试教了两件事

**一、`WingsAreLegal` 是死代码。** 我在飞机分支里写了一个守卫来执行「翅膀不能拆炸弹」,还为它写了测试。把守卫改坏,测试**照样绿** —— 因为含恰好一个四张的手牌一定先走到四带二分支并在那里被拒,到不了飞机分支。守卫已删,规则的实际执行点(那个分支末尾的 `return null`)写上了注释,并且验证过它是承重的:去掉它,一条测试变红。

> 一个看起来承重的守卫,和一个真的承重的守卫,只有在被改坏的时候才分得出来。

**二、我对 seed 0 的后果写错了。** 原注释说状态 0 会让洗牌"退化成永远不洗" —— 不对:状态恒为 0 时每次的交换目标都是 0 号位,牌确实动了,54 张也还各一次。真正的后果是**熵全丢**:任何落到零状态的种子发出同一副牌。原来那条断言("第一手不等于牌堆前 17 张")因此在守卫被改坏之后照样绿。现在钉的是精确的那条:`FromSeed(0)` 必须与直接给出替代常数的种子发出同一副牌。
