## Why

计分类是唯一一个还没有任何游戏的类别。对战内核有四款、闯关内核有两款,而计分类的表格行从第一天起就只写着「俄罗斯方块」。

## 先质疑 roadmap 自己的拆分

roadmap 写的是 `add-score-attack-core` + `add-tetris`,即**先造内核,再加游戏**。本变更**不这么做**,理由是这个仓库自己的历史:

> `generalize-puzzle-rules` — 华容道的使能重构,也是这个仓库**第四次**遇到同一个错误:一个被它唯一的实现塑形的接口,因为同族的第二个实现从未反驳它而被当成通用的。

`add-puzzle-core` 先造了 `IPuzzleRules`,只有成语纵横一个实现,还配了一个**形状像成语纵横的假实现**去证明"接缝是通用的" —— 而假的无法反驳它被写下时的假设。华容道一来,`Validate` 没有 layout、`Score` 看不到步数,两处都得改。

**计分类只有一款游戏在规划里。** 先给它造一个注册表接口,是在没有第二个实现的情况下猜通用形状 —— 与那次一模一样的赌注,而且赔率更差:那次至少有六款棋在路上。

所以本变更做**俄罗斯方块本身**,以及它真正需要的持久化。持久化实体命名为通用的(`ScoreRun`),因为那是**数据**而不是接缝 —— 数据形状错了改一列,接缝形状错了改每个实现。`IScoreAttackRules` 注册表**不造**:第二款计分游戏出现那天,内核从两个真实现之间长出来,而不是从一个实现加一个假实现之间。

## 分数凭什么可信 —— 第三种权威模型

这是整个类别的核心问题,而它没有前两个内核那样现成的答案:

| 游戏 | 权威来自 |
| --- | --- |
| 成语纵横 | **扣留**答案 —— 客户端没有答案,伪造不出解 |
| 华容道 | **重放**每一步 —— 什么都不藏,但服务端重跑一遍才认 |
| 俄罗斯方块 | **重放**,但重放的是**放置**而不是按键 |

游戏循环必须在客户端 —— 60 fps 的下落不可能每帧过服务端。所以客户端会报一个分数,而**客户端报的数字不可信**。

### 为什么不重放按键序列

最直觉的做法是让客户端提交完整输入流(左/右/旋转/软降/硬降),服务端跑同一份模拟。**不做**,理由是它要求两份模拟**逐帧一致**,包括重力间隔、锁定延迟、软降速率、等级提升曲线。任何一处差一帧,重放结果就不同,而**症状是一局合法的游戏被拒**——玩家看到的是"我明明打完了,它说我作弊"。

这正是这个仓库反复拒绝的形状:两个必须位对位一致的真源。`add-web-xiangqi` 拒绝把象棋规则港到 TypeScript,理由一字不差。

### 为什么放置是正确的粒度

提交的是**每个方块最终停在哪里**:`(pieceIndex, rotation, column)`。服务端从种子生成方块序列,按顺序把每个放置**落**下去(算它停在哪一行)、消行、计分。

- **不涉及任何计时。** 重力、锁定延迟、软降全都不进重放。
- 每个放置**可判定**:那个形状在那个列那个旋转下合法吗?落下后停在哪?消了几行?
- 粒度与华容道的"一次滑动"同级 —— 而那个模型已经被一款真游戏验过。

方块序列 MUST 由**服务端**的种子决定,否则客户端可以挑对自己有利的方块。种子随 run 开始下发,客户端与服务端用同一个确定性生成器。

**这个生成器是本变更唯一容许的"两份实现"**,而它容许的理由与其它地方不同:它是一个纯函数 `seed → 方块序列`,没有状态、没有计时、可以用一条测试逐项对齐(前 N 个方块必须完全相同)。它不一致的症状也不是"合法游戏被拒",而是"第一个方块就不对",立刻可见。

### 诚实的限制,写下来

重放保证的是**分数与放置一致**,不是**放置出自人手**。一个离线求解器可以按服务端给的种子算出接近最优的放置序列并提交。

这一条不假装被解决了。所有分数榜都有这个问题,而重放至少把"随便报个数"降级成"你得真的算出一个能拿那个分的下法"。`add-xiangqi-ai` 立下的规矩在这里同样适用:**一个无法验证的断言比没有断言更糟** —— 所以本变更不声称"分数一定是人打出来的"。

## What Changes

- `ScoreRun` 实体:`UserId`、`GameKey`、`Seed`、`StartedAt`、`FinishedAt`、`Score`、`Lines`、`Level`、`RowVersion`。用时与结束时刻取**服务端时钟**,与 `PuzzleAttempt` 同规。
- 一次 run **不可复用**:已 `FinishedAt` 的 run 再提交 MUST 拒绝;他人的 run MUST 返回 404(不泄漏 id 存在),与 `PuzzleAttempt` 逐条对齐。
- `TetrisRules`:七种标准方块、10×20 场地、确定性方块生成、放置合法性、消行、计分(标准 1/2/3/4 行 = 100/300/500/800 × 等级)。
- `POST /api/score-runs` 开一次 run(返回 id + seed);`POST /api/score-runs/{id}/submit` 提交放置序列,服务端重放并写入分数。
- 周期榜:`GET /api/score-runs/leaderboard?gameKey=tetris&window=week|month|all`。

## Impact

- 新 spec:`tetris`。
- 受影响代码:Domain 新增 `Tetris/` 与 `ScoreRuns/`;Application 新增两个命令一个查询;Infrastructure 一个迁移。
- **不新增注册表接口。** 见上。
- **无 UI。** 与 `add-xiangqi` / `add-idiom-chain` 同样的拆法:规则先落地并可用真实 HTTP 验证,UI 是下一个变更。
