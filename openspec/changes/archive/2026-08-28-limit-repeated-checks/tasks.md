## 2. 测试:两端都钉,而且要有反面

测试历史 **MUST 由逐步调用 `Apply` 累积**,不能手拼 `PlayedMove`:重放不校验历史里的步,
手拼的历史可以是一局不可能的棋,那时断言测的是别的东西。这一条先写成测试辅助函数,
让它不可能被绕过。

- [x] 第 3 次同一个将军 → 接受(`Ongoing`)。
- [x] 第 4 次 → 抛,码 `repeated-check`。
- [x] **反面对照:**第 4 次同一个**不将军**的局面 → 接受。少了它,一个把所有重复都拒掉的实现
      也能通过上面两条。
- [x] 将死仍然判胜(将军 + 对方无着)。**不要写成「同时达到上限又将死」** —— 那个组合
      构造不出来:局面相同 ⇒ 合法着法集合相同 ⇒ 若此刻将死则此前那次也将死,棋早该结束了。
      所以「将死优先」那个分支**没有任何测试能让它红**,这件事要如实写进 JOURNAL,
      而不是拿一条恒真的断言充数。
- [x] `xiangqi-endgame` 里同样被拒 —— 共用那一份的可执行形式。
- [x] `LegalMoves`:被禁的那一步不在里面,**而其余着法还在**。两半都要,否则一个返回空表的
      实现也能通过。
- [x] 标准开局(`xiangqi` 键)那条用真棋走出来:炮往复将军、对方炮堵与撤。**每一手都过 `Apply`**,
      所以走错一手会当场红,而不是悄悄测了别的东西。
- [x] 变异:上限常量改成 99 → 「第 4 次被拒」必须红;改成 0 → 「第 3 次接受」必须红;
      删掉「不将军就不管」那个短路 → 反面对照必须红;删掉 `LegalMoves` 的过滤 →
      枚举那条必须红。**每一条都要看到红,并且确认是 build 成功之后的红。**
      「把将死判定挪到上限之后」**不是**一个有效变异 —— 它两种顺序结果相同(见上),
      所以它不会红,而那不是测试的漏洞。
- [x] 既有 1500+ 后端测试一条不改地通过 —— 这条规则只在「将军 + 重复」同时成立时才动手。
