# add-leave-game-guard

对局进行中点走别处,先弹框确认。

## Why

今天点 header 里的任何一个链接,页面直接就走了。而**「走了」在四条线上各是什么后果,是量出来的,不是猜的**:

| 页面 | 离开时真正发生的事 | 依据 |
| --- | --- | --- |
| 房间页(六款对战棋) | `ngOnDestroy` **只调 `hub.leaveRoom`** —— 退出 SignalR 组,**座位还在你名下**。于是回合计时继续走,而你看不见棋盘了 → **超时判负** | `room-page.ts:392`,以及 `web-game-board` spec 明写「不因关闭 tab 放弃玩家位」 |
| 华容道关卡 | 每一步只存在**客户端**,通关时才 `submit(attemptId, { moves })` → 走了就全丢 | `klotski/play.ts:195` |
| 成语纵横关卡 | 每解一个词确实提交了服务端,**但 `StartPuzzleAttempt` 永远 `PuzzleAttempt.Start(Guid.NewGuid(), …)`** —— 没有续接,重进就是新的一次 | `StartPuzzleAttemptCommandHandler.cs:43` |
| 俄罗斯方块 | 一局结束才提交成绩 → 走了这一局不算 | `tetris/play.ts` 的 `Phase` |

**房间页那条最值得说:** 离开**不会**结束对局,也不会让出座位 —— 它把你变成一个还在局里、但看不见棋盘的人。**一个静默的超时负,和一次主动认输,在战绩里长得一模一样。**

## What Changes

- 加一个 `CanDeactivateFn` —— `leaveGameGuard`,**挂在每一条路由上**,而不是挑几条挂。
- 组件用**鸭子类型**的可选方法告诉守卫「现在走贵不贵」:

  ```ts
  export interface ConfirmsLeaving {
    /** 现在离开要警告什么;`null` = 走了不心疼。 */
    leaveWarningKey(): string | null;
  }
  ```

  守卫只认这个方法,**不认路由表、不认组件清单**。加第十款游戏时,实现这个方法就有守卫,不实现就没有 —— 而这正是「加一款游戏 = 落一个文件」那条约束要的形状。
- 四个组件实现它,判据各自不同:房间页是 `status === 'Playing' && 我占着座位`(**观众走了不问**);华容道是 `phase === 'playing' && moves().length > 0`(**一步没走的关卡不问**);成语纵横是解出过至少一个词且未通关;俄罗斯方块是 `phase` 为 `playing` / `paused` / `submitting`。
- 弹框用 **CDK Dialog**,四条线各自的文案走各自的 i18n 键 —— 因为**代价不一样**:房间页说的是「你还在这局里,超时会判负」,方块说的是「这一局不会计入排行」。一句通用的「确定离开?」把上面那张表抹平了。

## 刻意离开不能再问一遍

房间页自己有五处 `router.navigateByUrl`:登出、房间解散、重连后房间已不在、**点「离开房间」成功之后**、以及结束弹框里的「回大厅 / 看回放」。其中第四处最要命 —— **`rooms.leave()` 已经发出去了**,这时候再问「要走吗」是在问一件已经发生的事。

所以刻意的离开 SHALL 走一个 `leaveTo(url)`,它先把「正在退出」置真再导航;而 `leaveWarningKey()` 在退出中返回 `null`。

**而「记得走那个函数」不是机制。** 所以配一条测试:**房间页的源码里 `router.navigateByUrl` 只许出现在 `leaveTo` 里**。少写一处就变红,而不是等到有人在浏览器里撞见双重弹框。

## 不做 `beforeunload`

刷新和关标签页是另一条路径,而**两边的代价并不一样,这也是量出来的**:房间页刷新之后会**恢复**(REST 快照 + 重新入组,`web-game-board` 那条「重连协议」钉着);另外三条线**不会**。

**触发条件:** 有人因为刷新丢掉一局方块 / 一关华容道时,给那三个页面加 `beforeunload`。房间页不需要。

## 「离开房间」按钮也确认一次(已定)

它比误点 header **更贵**:`rooms.leave()` 会**让出座位**,这一局就真的结束了。而旁边的
「认输」要二次确认 —— 两个按钮挨着,一个问、一个不问,而不问的那个后果更重。

**判据用同一个:** 按钮在 `leaveWarningKey()` 非空时弹**同一个**弹框、说**同一句**话。
不是「按钮一条规则、守卫另一条规则」——两条规则会分叉,而分叉的表现是某一条路径悄悄
不问了。确认之后才置「正在退出」并发请求,所以**全程只弹一次**。

等待中的房间(房主解散空房间)`leaveWarningKey()` 是 `null`,所以不问 —— 那里没有对局
可丢。

## 判它成不成

- 每条路由都挂上了守卫 —— 判据是**走一遍 `routes` 数组**,而不是眼睛看。新增一条不挂的路由 MUST 变红。
- 两头都要有样本:**观众离开不弹框**、**一步没走的关卡不弹框**,与「进行中的对局弹框」在同一批测试里。
- 弹框里点「留下」MUST 真的留在原地(守卫返回 false),而不是弹完照样走。
