# drop-theme-token-mirrors

删掉每套主题在 TypeScript 里的 token 镜像。**它们守的是副本,不是真源**,而它们要每个用户在首屏付 **4.88 kB**。

## Why

`add-qq-game-theme` 把初始包顶到 **481.29 kB**,超预算 1.29。按 `CLAUDE.md` 里那条延期项自己写的做法 ——「**问什么是眼前载入而不必眼前载入的,并且靠打桩去量,不要推理**」—— 打桩量出来的答案是这个:把四份 `themes/*.ts` 从包里去掉,初始总量 **481.29 → 476.41 kB**,省 **4.88 kB**。

那不是猜的,是把 `register()` 的实参换成一个空对象、跑一次 `npm run build` 量到的。

### 它们买到的东西,和它们其实没买到的东西

镜像**确实**买到一样真东西:**编译期完整性** —— 一套主题的 TS 对象少一个字段就编译不过。这个仓库很看重这种保证(皮肤与 sound pack 都是靠它)。

但仔细看它守的是什么:**TS 对象不画画,CSS 画画。** 一套主题的 TS 镜像齐全、而 `tokens.css` 里那个块缺一项 —— **照样编译通过,照样画错**。那种情况只有 `check-styles.mjs` 抓得住,而它已经在抓,并且是**从 `@theme` 与 `[data-theme]` 选择器推导**的、CI 里会红的。

所以这层保证的位置是错的:**它保证副本完整,而真源的完整性由别人保证。** 一份被校验过完整性的副本,比一份没人校验的副本更容易让人相信 —— 而这正是它值得删的理由,不是留它的理由。

第二笔账:镜像是**手抄的第二真源**。每加一套主题、每改一个色值,都要在 `.ts` 和 `.css` 两处写同一个值。两处分叉时,**画面听 CSS 的,而校验听 TS 的** —— 于是校验会说「一切完整」而屏幕是错的。这正是本仓库判过五次的那个形状,只是这次两份都是我自己写的。

## What Changes

- 删掉 `src/app/core/theme/themes/{material,system,ink}.ts`。
- `ThemeService.register(name)` 不再收 token;`validateTokens` 一并删除。
- `theme.tokens.ts` **保留**,但职责收窄为「中性值的唯一定义处 + 契约的说明」—— `check-styles.mjs` 解析它里面的 `NEUTRAL_DECORATION`,所以它是生产源,不是文档。
- 顺手删两个零调用点的导出:`ThemeTokenSet` / `ThemeTokens` 类型(镜像走了就没有实现了),以及 `controlRadiusIsNeutral`（`extend-theme-tokens` 里加的,从未被调用 —— 和已经被否掉的 `--radius-pill`、已经被删掉的 `--accent` 同一个形状,这是第三次）。

**扩展点因此变简单了**:加一套主题从「两份 TS 对象 + 一段 CSS + 一行 register」变成「**一段 CSS + 一行 register**」。

## 不做的事

- **不动 `check-styles.mjs` 的任何一条断言。** 它是这个变更之后唯一的完整性保证,所以它必须一行不改地继续绿 —— 而如果它需要被放宽才能通过,那说明这个变更是错的。
- 不动任何主题的**色值**。屏幕上零变化,而判据是初始包变小、`data-theme` 行为不变。
