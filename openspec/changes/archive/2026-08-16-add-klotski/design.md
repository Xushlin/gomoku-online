# 设计决策

## D1 —— 一步 = 一格

一次「移动」有两种数法：滑一格算一步，或者同一枚子沿同一方向连滑算一步。经典的「横刀立马 81 步」用的是后者，前者会得到一个更大的数。

选**一格一步**。理由是它无歧义：客户端的一次拖拽可能跨两格，服务端不该去猜玩家「本来想」算几步。把移动切成最小单位之后，重放、计数、计分三件事用的是同一个定义。

代价是数字比玩家在别处见过的大。这不是问题，因为**本变更不引用任何外部数字** —— 见 D2。

## D2 —— `minMoves` 是算出来的，不是抄来的

`add-xiangqi-ai` 拒绝声称任何难度「不可战胜」，理由是**一个验不了的断言比没有断言更糟**。同一条在这里的形式是：不要把记忆里的 81 或 116 写进关卡数据。

关卡产物里的 `minMoves` 由**离线 A\* 搜索**产生（启发函数取曹操到出口的曼哈顿距离，可采纳，所以结果最优），并且有一条测试重新跑一遍搜索、断言结果与产物一致。这个数字这个仓库随时能复现。

顺带记一句诚实的话：这不保证它等于任何书上的数，因为书上的数用的是另一种数法（D1）。

## D3 —— 华容道没有秘密，它的权威来自「重放」而不是「隐藏」

成语纵横的服务端权威建立在**不下发**上：答案不出服务端，所以客户端伪造不了通关。

华容道什么都不藏。棋子、盘面、出口、滑动规则全在客户端 —— 一个判不了滑动的客户端连动画都做不出来。

它的权威建立在**重新执行**上：服务端从关卡自己的起始布局重放玩家声称走过的每一步，任何一步不合法、或走完曹操不在出口，就整份作废。

> 同一条平台规则（计分只用服务端可观测信号），两种完全不同的机制。

这条要写进规范，因为它决定了 `SolutionJson` 里该放什么：既然没有要藏的东西，它就只放计分需要的那一个参数 `{ "minMoves": N }`。给它编造一份「答案」只会让下一个读代码的人以为那里有秘密。

## D4 —— 提示是搜出来的，不是存下来的

存一条最优路径，玩家离开它三步之后就没用了 —— 更糟的是它会给出一个**在当前局面下不是最优、甚至不合法**的建议。

`Hint` 因此对**玩家上报的当前局面**跑同一套 A\*，返回最短解上的下一步。这也正是它值一颗星的原因。

按平台契约，上报缺失或解析不了时退化到「从初始布局出发的第一步」，而不是报错。

性能：A\* 从任意可达局面出发都在同一个连通分量里，规模是几万个状态量级；启发函数把实际展开数压得远小于此。会有一条测试记录实测耗时 —— **如果它超过百毫秒量级，那是需要写下来的事实，不是需要藏起来的事实。**

## D5 —— 计分公式，以及 `Mistakes` 恒为 0

```
cost  = 步数 / minMoves
stars = 3 if cost ≤ 1.0 且 hints = 0
        2 if cost ≤ 1.4 且 hints ≤ 2
        1 otherwise
```

`Mistakes` **不参与**。它对本游戏结构性地恒为 0：那个计数器只有客户端调用 `check` 才增长，而华容道的客户端没有理由调（D6）。把一个永远为 0 的量写进公式，等于写了一段永远不执行的代码。

`generalize-puzzle-rules` 已经把「计分公式 MUST NOT 要求 `Mistakes` 被填充过」写进了平台规范，这里是第一个用到它的游戏。

## D6 —— 为什么客户端不会调 `check`

成语纵横需要 `check`，因为客户端**没有答案**：一条成语填满的瞬间要就地判对错，客户端自己做不到。

华容道不一样：能不能滑，由公开的盘面和公开的规则决定，客户端自己判得了。为每一次滑动发一个请求，对一局上百步的谜题既慢又什么都没换来 —— 服务端最后无论如何都要重放整条路径。

`CheckPartial` 仍然实现（接口要求它，而抛异常或恒返回 false 都会污染错误计数）。它的语义是「这段前缀是否全部合法」，答对时附带 `{"caoCaoOut": bool}` —— 也就是 puzzle-core 文档里预告过的「华容道要说『这一步把曹操挪出来了』」。写它是为了它被调用时行为正确，不是因为预期它会被调用。

## D7 —— 关卡从哪来

和成语纵横同一条路：一个离线生成器写出 `backend/data/levels/klotski.json`，产物**提交进仓库**，一个幂等 seeder 在启动时灌库。关卡数据不进 migration。

生成器不「生成」布局 —— 华容道的经典局面是文化物，不是随机产物。它读入手写的布局，跑 A\* 求 `minMoves`，写出产物。也就是说：**布局是人写的，难度是算出来的。**

## D8 —— seeder：新增一个，还是把既有的那个变通用

`CrosswordLevelSeeder` 除了两个常量（游戏键、产物路径）之外没有任何成语纵横专属的东西。复制一份会得到第二份同样的代码。

因此把它提升为 `PuzzleLevelSeeder`，游戏键与路径变成构造参数。这**不违反**继承来的验收条件：它在 `Infrastructure/Persistence/` 下，不在 puzzle-core 的领域层、handler 层或端点里，而且它本来就是「关卡怎么进库」这件事的实现，不是规则接缝。

判据仍然按字面执行：`git diff --name-only` 里不得出现 `Gewu.Domain/Puzzles/`、`Gewu.Application/Features/Puzzles/` 或谜题端点。
