## Why

俄罗斯方块的后端整套都在(`add-tetris`:`ScoreRun`、三个端点、重放、周期榜),而**没有任何界面**。`GAME_REGISTRY` 里它还是 `planned`,计分类这一整个类别因此在屏幕上仍然不存在。

## 这一款游戏与前六款的根本区别

前六款的客户端**要么不需要规则,要么规则可以不在客户端**:

| 游戏 | 客户端知道规则吗 | 为什么 |
| --- | --- | --- |
| 五子棋 / 一字棋 | 不需要 | 点一个空格,服务端判 |
| 中国象棋 | **刻意不知道** | 港一份 TypeScript 规则会造出第二个真源 |
| 成语纵横 | 不可能知道 | 答案被扣留在服务端 |
| 华容道 | 必须知道一条 | 「滑进相邻空格」是画拖拽所必需的 |
| 成语接龙 | 知道两条、第三条不知道 | 词典有 30,895 条,不该带 |
| **俄罗斯方块** | **必须知道全部** | 60 fps 的下落不可能每帧过服务端 |

`add-web-klotski` 立的判据是:**不是「客户端该不该知道规则」,而是「知道了会不会造出一个能悄悄分叉的第二真源」**。这一款在这个判据下的答案是:会造出第二份实现,但**分叉不会悄悄** —— 服务端重放每一个放置,客户端的场地模型一旦跑偏,提交就会被拒。分叉是**被检出的**,不是被容忍的。

## 最关键的一条:服务端的重放模型是「每个方块在它那一列直着落下」

`TetrisField.LandingRow` 从顶上往下找第一个碰撞点。它不知道玩家是怎么把方块弄到那里的,也不需要知道 —— 提交的是 `(rotation, column)`,服务端自己算它停在哪。

**这条模型有一个后果,而它决定了整个游戏循环的设计**:如果客户端允许把方块**塞到悬空块底下**(tuck),那个落点就不是「在这一列直着落下」能到达的,于是服务端重放出来的位置不同 —— 或者干脆判非法。

而症状是**整局在最后一刻被拒**。这正是 `add-tetris` 拒绝重放按键序列时给出的理由:「玩家看到的是『我明明打完了,它说我作弊』」。用一个允许 tuck 的客户端配一个直落的服务端,等于把那个失败模式从计时不一致换成几何不一致,一点没少。

所以:**客户端 MUST 维持「当前方块可以由本列直落到达」这个不变式**,横移与旋转如果会破坏它就被拒绝(手感上等同于撞墙)。它禁掉的恰好只有一件事 —— 塞进悬空块底下 —— 而换来的是**每一个放置由构造保证可重放**。

被否决的两个替代方案:

- **让服务端接受任意落点**(提交 `(rotation, column, row)`)。那等于服务端不再判定落点,只判定「这个位置空着」—— 而「空着」在一个客户端能任意摆放的模型里几乎总是真的。重放的价值就没了。
- **做成无重力的摆放游戏**(在顶上摆好再硬降)。它确实平凡可重放,但下落的时间压力**就是**这个游戏。

## 分数:屏幕上跳的那个数字不是权威的

客户端必须自己算分并实时显示 —— 没有第二种可能。但**记录下来的是服务端重放出的那个**。

所以结算面板显示的 MUST 是服务端返回的数字,而不是客户端自己那个。两者不同就是客户端有 bug;不同的时候玩家会看到数字在结算时变一下,而那比「显示一个服务端根本没记下的分数」诚实。

守这条的机制不是断言两者相等(那需要服务端),而是一条**只用客户端就能跑**的不变式:**客户端的实时分数,必须等于把它自己记下的那串放置重放一遍得到的分数**。这条测试同时抓住「游戏循环算错分」和「记录的放置与实际落点不一致」两类 bug,而后者正是上面那个不变式要防的东西。

## 生成器是唯一容许的两份实现,而这次有对照数据

`tetris` spec 早就写了这一条,理由是它是纯函数、可以用一条测试逐项对齐。`add-tetris` 用一份 Python 实现实测过:seed `20260818` 的前 21 个方块(三整袋)与 C# 完全相同。TypeScript 这一份 MUST 用同一批数字钉住 —— **形状表的原点约定(`Normalise`)也要港**,否则 `column` 的含义差一个常量,每一个放置都错。

## What Changes

- `games/tetris/` 下的引擎:`Tetromino`(七种 × 四旋转,由旋转态 0 推导)、`pieceSequence(seed, n)`(xorshift32 + 七袋)、`TetrisField`(`landingRow` / `placeAndClear`)、`scoreForClear`。全部是 C# 那几个类的逐项移植。
- 游戏页 `/g/tetris`:开局取种子 → 客户端跑循环 → 每次锁定记一个 `(rotation, column)` → 结束时提交 → 显示**服务端**返回的分数。硬降落点用 `landingRow` 画预览幽灵。
- 键盘(←/→/↑/↓/空格/P)与触屏按钮**都要有** —— 375 px 是硬要求,而触屏上没有方向键。
- 分数榜页 `/g/:gameKey/scores`,窗口 `week` / `month` / `all` 三选一。它**不是** `/g/:gameKey/leaderboard`:那一页是 ELO 榜,行的形状(分/胜/负/和)与这里(分/行数/等级/时刻)不同,数据源也是另一个端点。
- 目录页给 `category: 'score'` 的游戏加一个分数榜链接。这不引入任何副本 —— `category` 已经在 manifest 里,而 ELO 榜那个链接由服务端的 `isRated` 把关是因为它防的是「永久空榜」,计分类没有对应的服务端标志,`category` 就是那个结构性事实。
- manifest:`planned` → `available`,`launchRoute: '/g/tetris'`。
- i18n:`zh-CN` + `en` 各一个 `tetris` 块。
