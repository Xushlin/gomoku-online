# add-idiom-guess

猜成语 —— 看释义,把成语里挖掉的字填回去。**第十个游戏。**

## Why

用户要的。而这一个比看起来便宜:**它要的东西平台早就备好了,而且是写着名字备的。**

### 接缝里已经写着「猜成语」

`IPuzzleRules` 的文档在三处点名了它,不是巧合 —— 它是照着三个游戏设计的:

> 三个游戏的关卡形状差别极大(成语纵横是字格、华容道是滑块布局,**猜成语是一条释义**)

> 成语纵横要在一条成语填满的瞬间显示它的释义…**猜成语要给出处**,都是同一个需求

所以 `PuzzlePartialResult.PayloadJson` 这个字段是**为这个游戏留的**。

### 而 `puzzle-core` 的验收判据也已经写好,就等这一次

live spec 里那一条,原文:

> 新增一个单人关卡游戏 MUST 只需要:一个 `IPuzzleRules` 实现 + 一处 DI 注册。
> **这条此前由一个假实现验证,而假实现证明不了它。** …判据因此改为可执行的形式:
> **下一个游戏落地时,`git diff --name-only` 里 MUST NOT 出现本能力的任何文件。**

**猜成语就是那个「下一个游戏」。** 本变更的头号验收条件不是我定的,是它定的 —— 而它可执行。

### 数据早就在库里,量过了全量

`backend/data/idioms.curated.json`,**30,895** 条,不是抽样:

| | |
| --- | --- |
| 有释义的 | **12,580**(= tier1 1,171 + tier2 11,409,恰好,生僻层无释义) |
| 其中四字的 | **12,580 —— 全部**,没有例外 |
| 释义里直接含成语本身(直接泄题) | **51** |
| 有出处可作答对载荷的 | 12,271 |

### 而有一个数只有量全量才看得见,它直接改了设计

挖一个字、同时把释义摆在旁边 —— **那个被挖的字如果就写在释义里,答案是印在屏幕上的**。

| 四个字里有几个**没**出现在自己的释义里 | 条数 |
| --- | --- |
| 0 —— **一个都挖不了** | **2,914** |
| 1 | 3,527 |
| 2 | 2,859 |
| 3 | 1,678 |
| 4 | 1,551 |

**23% 的条目按天真的做法出出来的题,答案就印在题面上。** 抽 30 条大概率一条都碰不上,而这个仓库已经为「样本推出来的 MUST」付过两次账(梅花谱的「最后一手必须终局」、残局的「红先」)。

可用池 **9,615** 条(tier1 890 / tier2 8,725),其中 **9,363** 条有出处 —— 剩下 252 条没有,所以答对后的载荷 **MUST 容忍出处缺失**,不能假定它在。

## 设计

**一关 = 若干条成语**(与成语纵横同构:关卡是提交进仓库的产物,12 关,难度 1–12)。每条显示**释义**与四个格子,其中一个或多个被挖空。

- `CheckPartial` = 「第 k 条我填这个」→ 对 / 错;**对了才**回传出处(错了回 `null`,那是接口写死的规矩:答错时附带任何内容都等于借错误路径泄题)。
- `Validate` = N 条全对。
- `Hint` = 揭一个空格里的字。
- `Score` = 错误数 + 提示数 → 星级,与成语纵横同一类公式。

难度由**数据**给,不由手感给:tier(常用 / 可用)× 挖几个字。挖 2 个字的池子是 2,859 + 1,678 + 1,551 = **6,088** 条。

## 这一次**不会**证明什么,而这句话要写在前面

journal 里那条教训是本仓库犯过**四次**的:*一个接口被它唯一的实现塑形,而同一家族的第二个实现推翻不了它。* `IPuzzleRules` 就是这么被一个「照着成语纵横写的 fake」验过的,然后华容道一来,两个方法都得改。

**猜成语与成语纵横是同一家族** —— 都用同一本词典、都往格子里填字、关卡都是提交进仓库的产物。所以:

- 它**能**兑现「一个实现 + 一处注册」那条判据(那是关于**改动面**的,可执行);
- 它**不能**用来宣称 `IPuzzleRules` 更通用了。真正的检验要等一个不填格子的关卡游戏。

把这句写进提案,是因为上一次没写,代价是一个假的「已证明」在规格里躺了很久。

## What changes

**Backend** — 目标是 `git diff --name-only` 里**不出现 `Puzzles/` 下任何既有文件**:

- `IdiomGuessRules : IPuzzleRules`(新文件)+ 一处 DI 注册。
- `GameKeys.IdiomGuess` 一个常量。
- 一个**离线关卡生成器**(与成语纵横的生成器同类:显式种子、产物可复现),输出 `backend/data/levels/idiom-guess.json`,随仓库提交。
- 生成器 MUST 执行那条泄题规则:被挖的字 MUST NOT 出现在该条释义里。

**Web**:

- `/g/idiom-guess` 懒加载关卡列表 + 关卡页(复用既有 puzzle 路由与 API,零新增端点)。
- manifest `status: 'planned'` → `'available'`,并补 `launchRoute`(平台不变量:available ⇒ launchRoute 非空)。
- i18n 两个 locale。**成语内容保持中文**,与其它两个成语游戏同规矩。

## 顺带发现的一处已经为假的话

`game-emblem.ts` 里那个 `t` 字形的文档写着:

> Used by exactly two games, for the two characters that *are* their identity: 象棋's 帥 and 斗地主's 王.

而现在有**三个** manifest 用 `t` —— 猜成语的 `?` 早就在里面了。**一个手写的计数,已经是假的了**,和这个仓库记名的那类陷阱同宗。本变更顺手改掉。

(它旁边那条「字形不许压在填充形状上」的走查是**真**的,而且从 `GAME_REGISTRY` 派生 —— 那正是当年 `?` 隐形那次留下的机制。猜成语的三个格子都没有 `f`,所以是描边不是填充,`?` 看得见。)

## Non-goals

- **不碰 puzzle-core 的任何既有文件。** 碰了就说明该先写一个使能重构,而不是把这个游戏塞进去。
- **不新增任何 REST 端点** —— 关卡、进度、尝试、check、hint、submit 六条全是现成的。
- **不动词典**:不改导入器、不改分层、不加列。252 条没出处的就是没有。
- **不做多人对战**,不进 ELO / 天梯 —— 它是 puzzle 内核,与成语接龙(match 内核)是两回事。
- **不宣称 `IPuzzleRules` 因此更通用。** 见上。
