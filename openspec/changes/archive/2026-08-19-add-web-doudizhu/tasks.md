## 5. 实现记录

### 在真浏览器里叫了分、出了牌

一个真 doudizhu 房间(三个真账号:浏览器坐 0 号,另两个用 REST 入座),点了「Bid 3」再选一张
♣6 点「Play (1)」,服务端侧:

```
moves [(1, 0, 'bid:3'), (2, 0, 'play:M')]   currentSeat 1
alice: myHand len 19  counts [19, 17, 17]  table 0 M
bob:   myHand len 17  counts [19, 17, 17]  table 0 M
```

**两个 token 看到两个不同的手牌长度(19 / 17),而公开的张数与桌面完全相同** —— 按座位裁剪
在线上真的成立。叫到 3 分之后手牌从 17 变 20(底牌进手)、`kitty` 从 `null` 变成三张,也都是
在浏览器里点出来的。

375 px 下 19 张牌在屏幕上时 `overflow: 0`,没有任何元素横向溢出 ——
**这个检查在空手牌上是白测的**,而那正是 `generalize-lobby` 记下的教训。

### 两个在浏览器里发现的问题,单元测试都看不到

**一、一局流掉之后,牌桌还在画「出牌 / 不要」两个禁用按钮。** 一个点不动的按钮在屏幕上是个
问句:是我不能点,还是坏了?`phase === 'Finished'` 时整行不渲染。

**二、轮到 2 号座位时,侧栏写的是「白方走棋」—— 而那一桌上没有白方。** 判据改成
`seats.length > 2`,不是棋种键:座位表就在快照里,而为一个已经在手上的数字多要一个异步依赖,
是把同步事实变成加载态。

两条都补了断言。第二条尤其值得记:侧栏的这段文字**在四个两座位棋种下一直是对的**,而它对
第三个座位的答案是错的 —— 与 `SeatWire` 那次是同一个形状,只是这次在文案上。

### `mySide` 是这次真正的一般化

牌桌收 `mySeat` 而不是 `mySide`,而顺着它拉出来的是:`RoomPage.mySeat` 读 `seats`
(而不是 `black` / `white` —— 2 号座位在那两个字段里根本不出现,会被当成围观者),
`mySide` 由 `mySeat` 派生(同一个事实两处读法就是两个真源),`RoomSidebar` 也收 `mySeat`
(此前 2 号座位上的人拿不到辞局与离开按钮 —— 那是 `isPlayer = mySide !== 'spectator'` 的后果)。

### 牌桌不判合法性,而这一次连"部分判"都不做

`add-web-klotski` 定下的尺子:不问客户端该不该知道规则,而问**知道了会不会造出一个能与服务端
分叉的第二真源**。三个已有答案各不相同 —— 象棋不判、华容道判、成语接龙**分裂**(两条规则判、
第三条不判)。斗地主整个落在不判那一侧:牌型识别加压牌比较都在服务端,而客户端唯一判得出的
只有"桌上没牌所以不能过" —— 那一条不需要任何规则。

### 一件刻意没做的事

**没有把 `SayWord` 改名。** 斗地主的动作走的是同一个 hub 方法 —— 服务端
`SayWord(roomId, text)` 只是构造 `MakeMoveCommand(Text:)`,不看棋种键,所以它其实是**通用的
文本载荷路径**,只是名字是为成语接龙起的。没有为斗地主加第三个方法(同一个载荷两个入口就是
两处要一起维护的校验路径),也没有顺手改名 —— 那是服务端 + 契约 + 规格三处的事,值得单独一个
变更。**触发条件:第三个走文本载荷的棋种落地那天**,那时"为某一个棋种起的名字"会变成三处误导。
