# per-game-seat-labels

席位怎么称呼,由棋种自己说。

## Why

**在浏览器里量到的:** 一个象棋房的侧栏写着「黑方:eg1」「白方:eg2」,回合指示写着「白方回合」——
而那张盘上 0 号座位画的是 **帥**(红方),根本没有白方。侧栏把红方叫成黑方,把黑方叫成白方。

它**不是**新缺陷,也不只是象棋的事:

| 棋种 | 座位数 | 今天显示 | 应该显示 |
| --- | --- | --- | --- |
| 五子棋 | 2 | 黑方 / 白方 | 黑方 / 白方 ✓ |
| 一字棋 | 2 | 黑方 / 白方 | 黑方 / 白方 ✓ |
| **中国象棋** | 2 | 黑方 / 白方 | **红方 / 黑方** |
| **象棋残局** | 2 | 黑方 / 白方 | **红方 / 黑方** |
| **成语接龙** | 2 | 黑方 / 白方 | **先手 / 后手**(它没有颜色) |
| 斗地主 / 挖坑 | 3 | 座位号 | 座位号 ✓ |

三处代码各写了一份同样的两分支:房间侧栏、棋盘下的操作条、回放页标题区。

### 判据错在哪:它把「有没有白方」近似成了「有几个座位」

`web-game-board` 现有要求的原文是:

> 当前回合指示:两座位棋种读作 `game.turn.black-turn` / `white-turn`,座位数大于二的棋种
> MUST 说座位号 —— **「白方走棋」在一个没有白方的棋种里是错的**(`add-web-doudizhu` 修的)

**那句理由是对的,而它只被用在了座位数上。** 象棋和成语接龙都是「没有白方的棋种」,而它们
恰好有两个座位,于是同一条理由该拦的东西从判据的缝里过去了。这是一条**在稳态下正确、
在别的取值上说谎的代理量** —— 座位数与「席位有没有名字」在斗地主上一致,在象棋上不一致。

### 而规格里已经写着答案,写在一个括号里

`web-game-board` 的侧栏要求说:

> `seatCount == 2`:渲染「黑方 / 白方」两个座位(**象棋读作红 / 黑**)。

括号里那句就是对的答案,而它**没有机制**,而且同一条要求自己的 Scenario 与它相反:

> #### Scenario: 两座位棋种仍然说颜色
> - **THEN** 侧栏说「黑方 / 白方」—— 棋盘上就是黑白子

**所以这不是「代码没跟上规格」,是规格自己没有把那句括号变成判据。** 一条写在括号里的
例外没有测试守着,也没有实现读它 —— 它和没写是一样的。

### 顺带发现:一条 live 要求与已发布的代码相反

`web-doudizhu` 的「侧栏在座位多于两个时说座位号」写着:

> 判据是 `seats.length`,MUST NOT 是棋种键,也 **MUST NOT 去问棋种注册表要 `seatCount`**

而 `publish-seat-count` 早就推翻了它(`seats` 只含**在座的**座位,于是等待中的三座位房间
会被当成两座位渲染),侧栏与操作条今天读的都是描述符给的 `seatCount`。
**`openspec validate --strict` 看不见这种矛盾** —— 它验形状,不验真伪。本变更正在改这两条,
所以把它一并对齐,而不是留一条与代码相反的 MUST 在那里。

## What Changes

- `GameManifest` 多一个 `seatLabelKeys?: readonly string[]`:席位名按座位号排。
  **不填 = 这个棋种的席位没有名字,界面说座位号。**
- **缺省从「黑方 / 白方」改成「座位号」。** 这是本变更的要点:旧的缺省本身就是那个失效。
  一个忘了声明的棋种显示「第 1 位」—— 不好看,但它不会把红方叫成黑方。
- `GameCatalogService.byRoomKey(key)`:按房间的棋种键解析清单,匹配自己的 `key`
  **或**声明的 `companionRoomKeys`(残局房要用象棋那份)。它同时收拢大厅房间行里
  已经存在的那份「伴生键 → 主棋种」私拼表。
- 三处调用点(侧栏 / 操作条 / 回放标题区)改用同一个解析函数;操作条的「座位数大于二」
  分支**被删掉** —— 三座位棋种就是「没声明席位名」的一种,不再需要单独一支。
- i18n:新增 `game.seat.{black,white,red,first,second}` 与 `game.turn.side-turn`(编号那两个键复用既有的 `game.room.seat-label` / `game.turn.seat-turn`,不新造);退役 `game.room.seat-{black,white}` 与 `game.turn.{black,white}-turn`。
  **退役的键名不许重用。**
- 一条遍历 `GAME_REGISTRY` 的走查:每个声明的键两份 locale 都有文案;声明与不声明**两支
  都在样本里**;不同席位名组合**恰好三种**。

### 为什么在 manifest 上,而不是在服务端描述符上

`board-seats.ts` 的文档已经把这条界线画好了:「座位号 → 棋子颜色是一份**显示读法**,
不是线上格式」。席位名同理 —— 它是文案键,而文案不上线。服务端给的是**有几个座位**
(一个结构性事实),客户端答的是**它们叫什么**。两者不该由同一个数字回答,而今天正是
同一个数字在回答两个问题。

## 不做,而理由要写下来

**回放的三座位缺陷不在本变更里修。** 查回放页时发现:`GameReplayDto` 只有 `Black` / `White`
两个字段,而 `GetGameReplayQueryHandler` 无条件读 `room.BlackPlayerId` / `WhitePlayerId` ——
于是**一局已结束的斗地主,它的回放会静默丢掉 2 号座位**,并把另两人叫成黑方 / 白方。
没有任何测试覆盖三座位回放。

那是**契约**问题(DTO + handler + 前端 + 测试),不是文案问题;混进来会让这个变更同时改
显示层和契约层。本变更在回放页只修它**表达得出来**的那一半(两座位棋种的席位名),
并把那个缺陷单独记下来。

## Non-goals

- **不改领域 / DTO 的字段名。** `Room.BlackPlayerId` / `WhitePlayerId` 是座位 0 / 1 的派生读法,
  它们的文档写着为什么留着(87 处调用点读的正是「谁是黑方」),而三座位棋种本来就
  MUST NOT 用这两个名字(用 `PlayerAt`)。本变更只动**显示层**。
- 不改棋盘本身:`XiangqiBoard` 已经按 `web-xiangqi` 那条「**本条存在的目的是防止有人把它
  『修正』回去**」把 `Stone.Black` 画成红色。本变更与它同向,不碰它。
- 不给三座位棋种编席位名。斗地主的「地主 / 农民」由叫牌决定,不是座位属性 —— 座位号是
  那里的正确答案。
