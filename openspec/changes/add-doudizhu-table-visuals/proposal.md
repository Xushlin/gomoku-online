# add-doudizhu-table-visuals

## Why

斗地主能玩了,而它**不像一张牌桌**。牌是一个个方框里的「♣6」,三家是三张并排的卡片,
发牌与出牌都是瞬间换一批 DOM —— 没有一处告诉你刚刚发生了什么。

用户给的参照(QQ 游戏斗地主)里真正起作用的是四件事,而它们**都不需要新的服务端数据**:

1. 一张**桌子** —— 绿呢面、暗角,三家坐在桌边而不是排成一列;
2. **真牌面** —— 圆角、角标、两个大花色,而不是一个写着字的边框;
3. 对家的手牌是**一叠牌背**,张数看得见,而看不见是哪几张;
4. **发牌与出牌有动作** —— 牌从桌心散到手里,出的牌从出牌人的方位飞到桌心。

## What Changes

- `card-table` 重写模板与样式:felt 桌面、三个环绕的座位、真牌面、扇形重叠手牌、牌背叠。
- 新增 `card-table.css` —— **组件自己的样式表**,不是 `src/styles/` 下的全局文件。
  (提案原来写的是后者;全局样式首屏就要下载,量出来会把 480 kB 的预算顶穿,见 tasks §3.1。)
- `BoardSkinTokens` 加 `cards` 与 `felt` 两段,三个内置皮肤各补一份。
- 新增纯函数模块 `table-layout.ts`:座位环绕顺序、出牌方位、当前一轮的动作。
- 素材:用户提供的素材包里**四个花色图**(♠♣♥♦),降到 96×96 放 `public/cards/`。
- 后端:**零改动**。

## 五个决定

**一、牌面用 CSS 画,只有花色形状用素材。**
素材包有 54 张 420×600 的牌面,而它们**不能进这个仓库的暗色模式**:54 张定死的位图既不跟主题、
也不跟棋盘皮肤,而 CLAUDE.md 的硬规则是「组件里不许写死颜色」。这正是 `add-web-xiangqi` 已经
判过的同一个案子 —— 象棋的棋子没有用图,而是 `BoardSkinTokens.pieces`,并留下那条约束:
**皮肤挑的是深浅,不是色相**。牌面是它的下一个:纸面、边框、角标、牌背、桌面全部走 token,
而**花色的色相是这个游戏的身份**(♥ 必须是红的),所以花色用素材包的四张图,一张 2 KB 上下。
顺带的好处:`♥` 在部分平台会被渲染成彩色 emoji,而一张图不会。

**二、动画由「牌的身份」驱动,而不是由计时器。**
手牌用 `@for (card of hand(); track card.code)`,所以**一张牌的 DOM 节点只在这张牌第一次出现时
被创建** —— 把 `animation` 直接写在牌上,它就恰好在"这张牌到手"的那一刻放一次,之后重排、
别人出牌、快照刷新都不会重播(CSS 动画不会因为节点移动而重启)。于是:没有信号要清、没有
`setTimeout` 要取消、没有"动画放过了吗"这个状态。**同一个事实(牌的身份)同时驱动 DOM 与动画,
就没有第二个东西需要被记得去重置。**

发牌的散开也全在 CSS 里算得出:`--i`(第几张)、`--n`(共几张)、`--step`(重叠步长)三个变量
一摆,`translateX(calc((var(--n)/2 - var(--i)) * var(--step)))` 就是"从扇形正中出发"。

**三、出牌的方位来自一个纯函数,而不是量 DOM。**
`relativeSeat(seat, mySeat, total)` → `'self' | 'left' | 'right'`,三个值各对应一组 CSS 起点变量。
不需要 `getBoundingClientRect`,因此在 jsdom 里可测、可变异,而且**不在乎排版**:桌子在 375 px 下
换了摆法,方位仍然对。

**下家在右手边** —— 出牌逆时针,而俯视时从下方逆时针的下一个位置就是右边。这与
`others()` 现有的"从我的下一个座位开始"顺序一致,只是给了它一个屏幕方向。

**四、每家身边显示的是「当前一轮」的动作,而这一轮是算出来的,不是猜的。**
QQ 那张图里最有信息量的是「不要」两个字贴在人旁边。它可以完全从**已经公开的 `moves`** 里得到,
不需要任何规则知识:**从最后一手 `play:` 起到末尾的那一段就是当前一轮** —— 因为桌上那手牌就是
最后一手非 pass 的出牌,它之后只可能是 pass。叫分阶段同理,取全部 `bid:`。
新一轮开始时上一轮的「不要」会自己消失,因为那一段的起点前移了。

它 MUST NOT 用于任何判断。桌上"要压的那手牌"仍然只认服务端的 `tableCards`。

**五、`prefers-reduced-motion` 一关全关。**
不是可选项:一桌 20 张牌加上出牌,是这个 app 里动得最多的一屏。

## Impact

- Affected specs: `web-doudizhu`(新增三条 requirement)、`web-board-skins`(变量集那条)
- Affected code: `games/doudizhu/{card-table,table-layout,card-art}`、`src/styles/card-table.css`、
  `board-skin.tokens.ts` + 三个皮肤 + `board-skins.css`、`public/cards/`、两份 locale
- 后端:**零改动**
- **不在这次里**:发牌 / 出牌的**声音**。`add-game-sounds` 之后加一个事件要三个 pack 都补
  (少一个编译不过 —— 那是刻意的机制),它值一个自己的 change。触发条件:这一次的动画落地之后。
