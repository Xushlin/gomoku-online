# add-qq-game-theme

一个游戏厅的长相。第四套主题,并成为没有存过偏好的用户的默认。

## Why

用户的原话:「现在的 UI 太粗糙了不适合游戏的 UI」。量过之后「粗糙」有精确形态 —— `/home` 整个大厅 66 个元素,一共**四个视觉值**(1 种圆角、1 种阴影、2 种背景色、0 渐变),而九个棋种是**一个汉字贴在九张一模一样的白卡片上**。那不是做糙了,是**一套后台管理页的调色板被放进了游戏大厅**。

`extend-theme-tokens` 与 `drop-theme-token-mirrors` 已经把路铺好:token 契约能表达渐变、斜角与纹理,组件说角色名,而加一套主题只要「一段 CSS + 一行 register」。这个变更走那条路。

视觉稿经用户审阅通过(纯 CSS + 内联 SVG,不加位图)。

## What Changes

- `tokens.css` 追加 `[data-theme='qq-game']` 明暗两块。
- `DefaultThemeService` 加一行 `this.register('qq-game')`。
- `DEFAULT_THEME` 从 `'material'` 改成 `'qq-game'`。**只影响没有存过偏好的人** —— 解析顺序里 localStorage 优先。
- `header.theme.qq-game` 双语键。

### 这个变更还夹带了一次词汇扩展,而这笔账要算清

`tailwind.css` 出现在 diff 里,而扩展点写着「加主题 MUST NOT 修改 Tailwind config」。**不是违约,是这一版里混着两个动作**,而第二个是落到真实 DOM 上才发现必须做的:

shell 根是 `class="ground text-text"`,所以**同一个 `--color-text` 必须同时在大厅地面和牌面上可读**。而这套观感的核心恰恰是「暗色大厅 + 亮色牌面」—— 一个前景色满足不了两者。同理 `well` 定义成 `background-color: var(--color-bg)`(「凹陷 = 页面底色」)是扁平设计的说法;实体牌面上的凹槽应该是**更暗的牙白**,不是大厅的深青。

于是加三个 token:`--color-on-surface` / `--color-well` / `--color-on-well`,中性值分别是 `var(--color-text)` / `var(--color-bg)` / `var(--color-text)` —— 现有三套主题画出来一模一样。

**为什么 `extend-theme-tokens` 没发现这三个:** 它按「现有 class 属性的共现」推导角色和 token。那告诉你**当前设计需要什么**,对**另一种设计需要什么**是盲的。共现走查治好了「凭想象发明角色」,但治不了「现有设计把两个概念合成了一个」。

## 一处偏离审稿稿,理由是量出来的

审稿稿里**浅色**大厅也是深青。落到真实 DOM 上不成立(上面那条)。所以:**暗色一套才是那个深青大厅**,浅色一套改成竹席/宣纸的桌面 —— 同一套材质的另一种光。这是唯一一处与已批准样张不同的地方。

## 对比度

按**渐变的每一档**量,不是按平色回退值 —— 而这里有一个方向问题栽过一次:**深色文字在浅色渐变上,最差的是最暗那一档;浅色文字在深色渐变上,最差的是最亮那一档。** 取反会得到一个偏乐观 1.3 倍的数字。

明暗两套 × 六个前景色全部 ≥ 4.5:1,最低 4.51(浅色主按钮)。
