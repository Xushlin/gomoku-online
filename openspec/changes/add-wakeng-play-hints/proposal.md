# add-wakeng-play-hints

## Why

用户提的两件事:

1. **轮到自己、而手里根本要不起时,自动过牌** —— 不该让人点一下「不要」。
2. **一个提示按钮,直接把可出的一手牌点起来;连点轮换不同的出法。**

## 它们是同一个函数的两个消费者

**「要不起」就是「候选出牌列表为空」。** 所以这个变更的核心是**一个**领域函数:

> `WakengFollows.For(hand, table)` → 这手牌在当前局面下**全部**合法的出法。

- 自动过牌 = 列表为空;
- 提示 = 在列表里轮换。

写成两套逻辑会造出一个能自相矛盾的组合:提示说「你可以出这手」而自动过牌已经替你过了。
**一个事实两个读者,而不是两个事实。** 与 `add-tetris` 里「开局校验」与「重放」读同一个
`ScoreAttackGames` 是同一个形状。

## 谁来判「能不能出」—— 只能是服务端

这个仓库的硬规矩:**牌型识别与压牌比大小只在服务端,而它是这一局唯一的判据**。客户端再写
一遍就是一份会悄悄分叉的第二真源,而分叉在玩家眼里是「这游戏有 bug」——
`add-web-doudizhu` / `add-web-wakeng` 都是按这条判的。

所以客户端**不算**「我要不起」,它只是**照服务端算出来的事实行动**。
这与 `generalize-puzzle-rules` 写下的那句同源:*客户端给你的数不可采信,而服务端自己算出来的
数是一个服务端观测到的事实。*

## What changes

### 服务端 —— 一个纯函数,两个出口

- **`WakengFollows`(新)**:`For(IReadOnlyList<Card> hand, WakengCombo? onTable)`
  → `IReadOnlyList<IReadOnlyList<Card>>`,按「先弱后强」排。
  - `onTable == null`(自由首出):这手牌能组出的**全部**合法牌型。
  - 否则:**同型、同张数、更大**的那些 —— 挖坑没有炸弹,所以没有跨型压牌。
- **`seatView` 加 `canFollow: bool`** —— 「此刻轮到你时你出得起吗」。它**只对这个座位可见**,
  因为它由这个座位的手牌决定;`seatView` 正是那条通道。
  它 MUST NOT 是一个列表:候选出法可能有几十项,而每次广播都带着它是
  「一个没人渲染但所有人付钱的切片」(`generalize-lobby` 记过那笔账)。
- **`GET /api/rooms/{id}/hints`(新)** —— 按需返回调用者的候选出法。
  只有**在座玩家**能拿到自己的;围观者与非玩家 403/404。

### 客户端

- 轮到自己、桌上有牌、而 `canFollow === false` → **自动发 `pass`**。
  它仍然是一步真的棋、进历史、别人看得见「不要」——**不是跳过**。
- 出牌阶段多一个**提示**按钮:第一次点拉一次候选列表并选中第一手;再点换下一手,
  循环。选中的就是牌桌本来的选中态,所以点完可以直接按「出牌」,也可以手工改。

## 三处判断,写下来因为它们不是推导

1. **自动过牌由客户端发,而不是服务端替他走。** 服务端替走需要一个新接缝
   (「规则可以跳过一个座位」),而跳过又不能不记一手 `pass` —— 因为「连续两家过牌清桌」
   数的就是 pass。为一个便利动内核,换来的是同一件事的两种记法。
   客户端发一手真的 `pass` 走的是与真人完全相同的路径,而**它错了也只是多过一手**,
   不会让局面进入一个内核没见过的形状。
2. **`canFollow` 进 `seatView`,候选列表走按需查询。** 前者是一个布尔、每次快照都要用;
   后者只在按下按钮时要。把列表塞进广播是给每个人的每一帧都付一次钱。
3. **只做挖坑。** 斗地主的「压得住」要算炸弹、四带二、飞机带翅膀,而且炸弹跨型压 ——
   候选枚举大一个量级。挖坑没有炸弹,每一手合法牌都是「k 组等大的牌,k>1 时连续」,
   所以枚举是几行。**触发条件:斗地主也要这两个功能的那天**,而那时该问的是
   「这两个棋种的『出得起』真是同一种东西吗」——今天的答案是**不是**。

## 验收

- `WakengFollows.For` 的断言 MUST 覆盖:自由首出、同型同张数更大、**跨型压不住**
  (四头压不住同张数的顺子)、以及**空列表**(手里全是比桌上小的同型牌)。
- 「要不起」那条 MUST 用一个**真的要不起**的局面,并带**正面对照**(同一手牌换一个更小的
  桌面牌就出得起)—— 否则一个恒返回空的实现也会绿。
- `canFollow` 与 `For(...)` **必须一致**:一条断言在若干局面上逐个比对
  `canFollow == (For(...).Count > 0)`。**两个出口读同一个事实,那就该有一条断言把它们钉在一起。**
- 客户端:轮到自己且 `canFollow === false` → 自动发 `pass`;`true` → **不发**。两个方向都钉。
- 提示按钮:连点轮换,而且**不会选中一手服务端会拒的牌**(候选来自服务端)。
