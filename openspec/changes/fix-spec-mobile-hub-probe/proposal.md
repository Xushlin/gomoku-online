# fix-spec-mobile-hub-probe

把「连通性被证伪」收紧成**两个方向**,并把已经落地却没有要求守着的那条走查写进 spec。

## 为什么

`mobile-shell` 里那条要求现在是这么写的:

> 连上 `/hubs/match`、带查询串 JWT、`JoinRoom` 与 `MakeMove` 各成功一次。

**`JoinRoom` 和 `MakeMove` 都是出向。** 而探针自己的「正面对照」——「服务端上真的有这一步棋」——是用 **REST** 查的。所以整个证明里**没有一个字节是从 hub 流回客户端的**。

说准一点:探针里确实有一处 `connection.onclose(...)`,但那是**连接生命周期回调**,不接收服务端消息。**hub 方法订阅(`connection.on('X', ...)`)是 0 个。**

代价已经付过了:手机端订阅的是 `RoomStateChanged`,服务端发的是 `RoomState`,**入向从第一天起就是死的**,而这条要求是满足的、每一条测试是绿的。症状是对手加入后屏幕还写「等待中」、自己落了子盘面一动不动 —— 在真机上十分钟内看到,在此之前没有任何东西说过一句话。

**一个只测发送的连通性证明是半个证明。** 而这条要求会被下一个传输层继承:iOS、桌面壳的某条通道、或者哪天换掉 `signalr_netcore`。**收紧它的时机是教训还在手上的时候。**

## 改什么

### 一、`MODIFIED`:连通性证明 SHALL 覆盖两个方向

探针必须**收到**至少一条服务端推送并断言它的内容,而不只是发出去两个调用。判据不是「连上了」,是「服务端广播的一条状态到了客户端手里,而且里面有那一步棋」。

顺带把那个「正面对照」的说明改准:它当时叫正面对照,但它查的是 REST —— 它证明的是**服务端收到了**,不是**客户端收得到**。两件事,而混在一起正是这个缝的形状。

### 二、`ADDED`:客户端订阅的方法名 SHALL 从服务端源码派生

`test/hub_contract_test.dart` 在修那个 bug 时一起落了地,**但没有任何要求守着它**。一个有机制没要求的东西,是下一个整理代码的人第一个删掉的。

实测的数字值得写进去:服务端 **12** 个调用点、**10** 个不重复的方法名,web 端订阅的 10 个逐字对得上(那是同时写出来的,不是有机制),手机端订阅 **2** 个、其中 **1** 个不存在。

## 不改

- **不改标题。** 「在写任何 UI 之前被证伪」那半句对下一个传输层仍然成立 —— 顺序仍然是规格的一部分。所以是 `MODIFIED`,不需要 `RENAMED`。
- **不动 web 端**。它的 10 个名字对得上,但那是巧合不是机制;给它加同样的走查是另一笔账,触发条件:web 端第一次因为 hub 方法名对不上出问题。

## 规模

一条 `MODIFIED`、一条 `ADDED`,加上把 `test/hub_probe_test.dart` 扩成能证明入向。**估计 80–120 行**,大头是探针里那段「等一条推送到达」的代码和它的正面对照。
