# add-game-emblems

九个棋种在大厅里不再是九个汉字贴在九张一模一样的牌上。

## Why

用户的原话是「现在的 UI 太粗糙了不适合游戏的 UI」。量过之后「粗糙」有精确形态:`/home` 整个大厅 66 个元素,一共**四个视觉值**(1 种圆角、1 种阴影、2 种背景色、0 渐变),而九个棋种是**一个汉字 + 九张相同的白卡片**。

`extend-theme-tokens` / `drop-theme-token-mirrors` / `add-qq-game-theme` 三步换掉了牌面与大厅的材质,`drop-board-skin-mirrors` 腾出了首屏空间。剩下的就是那九个汉字。

## What Changes

- `GameManifest.icon: string`(一个字符)换成 `emblem: readonly EmblemShape[]` —— **24×24 网格上的一组图元**。
- 新增 `GameEmblem` 渲染组件,**独占**网格、描边宽度与线端形状。
- 十份清单(九个可玩 + 猜成语)各自声明自己的形状表。
- 两个调用点改用组件:大厅的 `games-strip` 与 `/games` 目录页(两处)。

## 为什么是形状表,不是九段 path

**独占才是重点,便宜是顺带的。** 十段手写 `path` 各自都有权选自己的描边粗细与视觉尺寸,那会得到十张画而不是一套纹章。形状表让清单**没有词汇**去指定这些。

顺带的账也记下来:十份形状表共 **1.27 kB**,平均 142 B,而 `card-art.ts` 一个花色剪影平均 575 B。**但整体代价不是 1.27 kB** —— 见 tasks 的 §5,渲染器编译后的模板比我估的贵四倍。

## 一处诚实的边界

纯 CSS/SVG 的上限是「精致的几何感」。这九个是**纹章**(身份色 + 图元),不是画师画的插画。看完仍觉得不够热闹的话,下一档就只剩位图,而位图不跟主题与暗色变。
