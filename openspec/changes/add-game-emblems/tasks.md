## 5. 计划之外

- [x] **我给出的字节数错了,而错在渲染器不在数据。** 形状表 1.27 kB 是对的;渲染器我估 0.4 kB,
      实测编译后模板 **1707 B**(四倍),加类型与映射 574 B。初始包 472.67 → **476.51 kB(+3.84)**,
      预算余量 7.33 → **3.49 kB**。**「数据很小」和「这件事很小」是两个说法。**

- [x] **用户在截图里抓到象棋与斗地主的字撑破了容器,而我为此量了三次,前两次都在量错的东西。**
      ① 按字宽估 —— CJK 字宽恰等于字号,于是「10 宽的卡片放 9 号字」看着放得下;
      ② `getBBox()` —— 它返回**行盒**,CJK 行盒高约 `1.45 ×` 字号,含一大截用不到的上伸部,
      据它判定会得到一个**假失败**(「上沿溢出」);
      ③ 把 SVG 画进 canvas **采样墨迹像素** —— 这个才回答问题。
      **对文字来说,能查到的盒子不是看得见的墨迹。**

- [x] **而真正反复取错的是容器边界,三次里错了三次:** 一个**描边**的容器,内沿是
      `半径 − 线宽/2`。象棋内圈 r=7、线宽 1.6 → 墨迹可用半径 **6.2**;「帥」9.5 号时半对角
      **6.79**(压线),7.5 号时 **5.36**。第一版的正面控制用 r=7,于是**它把坏的那版也判过了** ——
      一个边界取错的检查会安静地放行它本该拦住的东西。

- [x] **修好的动作来自一个错的理由。** 缩小字号是根据 ② 那次假失败做的,而它恰好也修好了
      真问题。**结论对而理由错,会把下一个人指向错的方向**,所以把量法与边界规则都写进了
      `game-emblem.ts` 的注释。

- [x] **第三个缺陷:猜成语中间那格是填充的,而 `?` 也是 `currentColor` —— 它是隐形的。**
      同色画在同色上不报错、不变红、不崩,只是看不见。

- [x] **一条变异证明我的走查是自指的:** 「一个棋种悄悄少掉一个形状」判绿,因为我拿渲染
      结果和**同一份数据**比。要测它就得把设计再抄一份。**那一类改动的守卫是试画页的人眼
      复核,不是测试** —— 写下来而不是补一个假测试。

- [x] **自动化的守卫弱于要求本身,并且写明了。** 「字形合不合容器」只有真浏览器能答
      (jsdom 无布局、无 `getBBox`、画不了 SVG 文字),所以自动化守的是**字号上界**与
      **不叠填充**;「容器改小了」仍需一次浏览器测量。
