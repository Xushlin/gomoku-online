## 7. 这一层的三个设计判断

### 一、服务端的重放模型逼出了一条游戏规则

`TetrisField.LandingRow` 从顶往下找第一个碰撞点。服务端不知道玩家怎么把方块弄过去,提交的只有
`(rotation, column)`。所以**塞到悬空块底下**(tuck)的落点不是本列直落能到达的:重放出来位置不同,
或者整局判非法 —— 而症状是**整局在最后一刻被拒**,玩家看到的是「我明明打完了,它说我作弊」。

那正是 `add-tetris` 拒绝重放按键序列时给的理由。用一个允许 tuck 的客户端配一个直落的服务端,
只是把不一致从计时换成几何。

所以客户端维持不变式「当前方块可以由本列直落到达」,破坏它的横移与旋转被拒(手感等同撞墙)。
**代价写在屏幕上**(一行说明文案),换来的是每个放置由构造保证可重放。

被否决的两个替代:让服务端接受任意落点(那等于服务端不再判定落点,重放的价值就没了);
做成无重力的摆放游戏(平凡可重放,但下落的时间压力**就是**这个游戏)。

顺带的推论:**没有锁定延迟**。给缓冲期的理由是「让玩家最后一刻塞进去」,而塞进去正是被禁的那件事
—— 缓冲期主要会买到一堆被拒绝的操作。这不是省事,是上面那条规则的后果。

### 二、屏幕上跳的分数不是权威的

客户端必须自己算分才能实时显示。但**记录的是服务端重放出的那个**,结算面板显示的也是它。
两者不同就是客户端有 bug;不同时玩家会看到数字在结算时变一下,而那比「显示一个服务端根本
没记下的分数」诚实。

守这条的机制不是「断言两者相等」(那要服务端),而是一条**只用客户端就能跑**的不变式:
实时分数必须等于把自己记录的那串放置重放一遍。它同时抓两类 bug —— 算分错、以及**记录的放置
与实际落点不一致**,而后者在屏幕上完全看不出来,因为屏幕画的是实际落点。

### 三、生成器这次有对照数据

`tetris` spec 早就说它是唯一容许两份实现的东西,理由是可逐项对齐。`add-tetris` 用 Python 实测过
seed `20260818` 的前 21 个方块(三整袋)。TypeScript 这份就用那 21 个钉住,**形状表的原点约定
(`normalise`)一起港** —— 少了它 `column` 会差一个随旋转态变化的常量,而屏幕上一切正常。

## 8. 三次自我纠正,每次都由测试或浏览器逼出来

### 一、我的不变式测试**没有**在测它声称在测的东西

「不让方块站到直落到不了的地方」原本只靠五局随机操作 + 三局贪心。变异验证:把
`commitIfLegal` 里的可达性检查整段删掉,**34 条全绿** —— 那些局恰好从没试过 tuck。

随机操作覆盖这条规则纯靠运气。补了一条**确定性**用例:seed 20260818 开局是 S,直落之后恰好留下
唯一一个悬空(`(18,5)` 有块、`(19,5)` 空),把下一个 L 挪到 6–8 列落到底,再向左一格就是 tuck。
它还带一个**正向对照**(向右移动必须仍然成功),否则一个「什么都拒绝」的实现也能过。

现在删掉检查 → 1 条红;删掉**出生位置**那条检查 → 1 条红。

### 二、出生位置也能违反那条不变式 —— 这是一个真缺陷,由不变式测试抓到

`spawn` 原来只检查「新方块的格子有没有被占」。但 L / J / T / S / Z 的某些旋转态**顶行不满**,
所以当堆到顶时,方块能合法地放在第 0 行,而它某个下方格子的**正上方**却有已占格。
那个位置无人可达,放置不可重放,整局会在提交时被拒。

只发生在一局输棋的最后几手 —— 正是没人会去看的地方。现在 `spawn` 也检查可达性,不可达即结束本局。

### 三、一条我写下的机制理由,被变异测试证伪

`piece-sequence.ts` 的注释原本写:「`>>> 0` 每一步都不是装饰」。变异:去掉**第一处** `>>> 0`,
**34 条全绿**。原因是 `<<`、`^`、`>>>` 操作的都是同一批 32 位,只有**最后**那次强制转换喂给 `%`。
去掉最后那次 → **6 条红**。

注释改成真话:只有最后一处是承重的,中间那些留着是为了可读(状态始终在无符号范围,便于跟 C# 对照)。

## 9. 浏览器实测(Development,scratch 库,前端 4321 / API 5233)

**一个只有浏览器能发现的缺陷:`No provider found for ScoreRunsApiService`。**

`ScoreRunsApiService` 是抽象类当 DI token,实现类挂了 `@Injectable({ providedIn: 'root' })`
—— 那注册的是**实现**,不是 token —— 而 `app.config.ts` 里少了 `{ provide, useClass }` 那一行。
**563 条单测全绿**,因为组件 spec 给的正是自己那个 stub。症状是 `/g/tetris` 静静地不渲染,
路由退回首页。

修完之后加了 `app.config.spec.ts`:token 清单由 `import.meta.glob` **推导**,不手写
(手写清单 + 走查测试是这个仓库在后端修过三次的缺陷)。变异验证:删掉那一行 → 红。

**那个 spec 自己也错了两版,而第一版错得有意思。** 第一版直接注入 glob 拿到的类对象,
**七个 token 全部失败**,包括六个在生产里好好工作的。原因:glob 的 module id 带 `.ts` 后缀,
而 `app.config.ts` 引的是不带后缀的路径,两者解析成**两个模块实例** —— 同名的两个类,
于是两个不同的 DI token。所以比较改成按**名字**:名字跨得过这个坎,类身份跨不过。
第二版把整个 `appConfig` 灌进 TestBed,于是 i18n 的 app-initializer 在销毁时留下
`EmptyError: no elements in sequence`,套件报告 **573 条通过 + 退出码 1**。现在只注入被测的那批
provider。

### 真的打了两局

| | 客户端实时显示 | 服务端返回 |
| --- | --- | --- |
| 第一局(全在中间硬降) | Score 0 | **0 points, 0 lines** |
| 第二局(按最低优先贪心走 39 手) | Score100 Lines1 Level1 | **100 points, 1 line, level 1** |

两局的客户端数字与服务端重放**完全一致** —— §7 那条自洽不变式,这次是对着真后端验的。
结算面板的文案是「This score comes from the server replaying your placements.」

### 榜

`/g/tetris/scores` 上三行:`🥇 alice…300 · 🥈 bob…100 · 🥉 TetrisPlayer 100`。
**TetrisPlayer 打了两局(0 分和 100 分),榜上只有一行** —— 每人一行的去重在浏览器里成立。
窗口按钮 `aria-pressed` 正确翻转,`All time` 会重新请求。

### 尺寸与配色

- **375 px,场地里 44 个方块在屏幕上时**:`scrollWidth === clientWidth === 375`,溢出 0;
  棋盘 343×535。**空场地上跑这条是白跑**(`generalize-lobby` 的教训)。
- 榜页 375 px,往一行里塞一个 200 字符的用户名:页面溢出 **0**,表格在自己的
  `overflow-x-auto` 盒子里横滚。注明:那个长名字是**注入 DOM 的**,不是服务端数据 ——
  它测的是布局规则,不是真实数据。
- 深色/浅色:方块从 `rgb(21,101,192)` 翻到 `rgb(144,202,249)`,空格边框、页面底色一起翻 ——
  全走 token,没有字面量。

### 目录页

tetris 卡片可点(`/g/tetris`),全站**只有一个** `/scores` 链接(tetris),
三个 ELO 榜链接(gomoku / idiom-chain / xiangqi)一个没动。

### 一条关于证据的限制

Browser 面板不显示时页面不产生帧,zoneless 的变更检测因此不跑。上面所有 DOM 读数都是在
手动 `ng.applyChanges` 之后取的,**所以它们说明的是内容,不是时序**。这一轮没有截图。
定时器与 HTTP 都照常工作 —— 重力真的在跑,提交真的发出去了。

## 10. 没做的

- **音效。** 消行/落地的音效包接口(`SoundService`)已经存在,但给它加两个音是独立的一件事,
  而且会牵动两个音效包各自补样本。
- **暂停时遮住场地。** 现在暂停只是停下重力;盘面仍然可见。要不要遮是个手感判断,留给玩过之后。
- **旋转的墙踢(wall kick)。** 刻意不做:踢出去的落点要满足同一条可达性不变式,
  所以一个「帮上忙」的踢,正是服务端重放不出来的那个。
